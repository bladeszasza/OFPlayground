# OFPlayground ASP 0.1 profile

Specification pin: [`17af7df6e48275f01233e8c0182f28e452f5f505`](https://github.com/AgentStatusProtocol/spec/tree/17af7df6e48275f01233e8c0182f28e452f5f505). The adjacent JSON Schema and MIT license are copied unchanged from that revision. Behavioral requirements also come from the supplied [paper v1](https://arxiv.org/abs/2610.21538v1), sections 5–8 and 12. The schema is explicitly non-normative; these decisions describe a local implementation profile, not certification.

This document fixes draft ambiguities before implementing the service. Implementation and test evidence is tracked in [the status ledger](../../implementation-status.md).

1. ASP remains separate from OFP. Five independent dimensions are retained. Task cells are keyed by task ID; floor cells by conversation ID. Unknown `x-...` values are preserved and labeled unknown.
2. Credential principals identify the sender. An event's `source` must match the principal's role. Self credentials are bound to one agent; independent reporters are scoped to authorized agents. Observer permission is separate. A caller cannot choose operator authority by changing JSON. Credentials never appear in URLs, journal entries or status events.
3. Ordering is per target agent and credential principal, not merely per role. Equal sequences with different event IDs are journaled but ignored, as are lower sequences. Duplicate IDs return acceptance without an additional journal record. Re-registering the same identity requires continuing its sequence; restarting a new runtime normally creates a new instance ID. Timestamps describe assertions; server receive time drives liveness.
4. Ingest and state persistence commit together before publishing a stream update. SQLite holds the append-only retained journal, reduced snapshots and ordering watermarks. Retention deliberately removes the oldest journal rows; snapshots/watermarks survive. An expired/future stream cursor gets an explicit gap and snapshot. An observer attaches and captures its replay cutoff without yielding between those operations. A slow observer is disconnected and resumes from its last cursor.
5. Only an accepted newer self event refreshes liveness. At 2.5 declared intervals the server assigns unreachable and marks retained tasks/floors stale. A returning self event restores its declared lifecycle or online. Independent reports, duplicates and old events cannot keep a silent agent alive. Clean deregistration stays offline.
6. Stall detection requires an explicitly declared threshold and at least one working/retrying task. Heartbeats then require progressSeq. Progress changes only at real work milestones. Designed input/approval/delegation/queue waits are exempt. A newer progress heartbeat restores the last self-reported health. Server liveness and stall transitions are journal events with server provenance. Optional task deadlines are measured from the server's receipt of working, not the caller's clock.
7. Governance uses operator > guardrail > self, including clearing a restriction. Supervisor/peer governance is rejected unless those principals are separately granted a guardrail/operator credential. Peer/independent health assertions remain alongside self health. A supervisor may report crashed; the next self event restores the agent as defined for liveness. Terminal tasks cannot transition out of their terminal state.
8. This state-only profile accepts allowlisted reason/activity codes and numeric metric keys. It rejects arbitrary extra fields and extension namespaces until explicitly supported. The local extension carries only bounded identifiers and enforcement labels. Free-text prompts, responses, exception messages and keys do not belong in status. Names are configured labels; operators remain responsible for not using secrets as labels.
9. Events are at most 16 KiB, batches at most 64 events and 1 MiB. Ingest is rate-limited per credential, with 429 and Retry-After. All snapshot, history and streaming routes require observer authorization. A standalone server binds loopback by default; non-local service requires TLS termination. No active probes, OTLP ingest, federation or multi-tenant guarantees in this release.
10. Reporting governance does not enforce it. The runtime adapter must separately acknowledge and enforce quarantine by blocking new work/floor grants and applying cancellation policy. The UI must expose requested, acknowledged and enforced outcomes separately; absence of enforcement cannot be displayed as success.

A supervisor-observed crash is retained rather than later replaced with the less specific unreachable inference; retained scopes become stale. A new self event can restore contact. Retry transitions alone do not reset the stall clock. Event IDs survive journal retention in a separate deduplication table, whose disk use grows with accepted IDs; archive/rotate this local store deliberately for long-lived installations. These profile decisions have behavioral regressions.
